# K02 — decision log

Append-only. History; never read whole. The current position is `docs/K02_STATE.md`.

## 2026-09-19 — Unit models declare rows *and* evaluate causally

**Question.** Is a SYN-001 unit model a contributor of residual rows, or a causal evaluator?

**Choice: both.** ADR 0008 D4.3 names "K02's first heater *residual*" and fixes two of its values
exactly, so rows are not optional. Plan §4.2's acceptance evidence (nominal, single-phase,
zero-flow, cache on/off, perturbed input) is evaluator-shaped, and the mixer's v0.0 enthalpy
closure is an inner bracketed solve that has no residual form at all. Blueprint §5.1 allows a
native equation model to supply both, and keeping them in one object lets each be checked against
the other.

**Rejected:** evaluators only, deferring rows to K03 — contradicts D4.3, which names K02.

**Carried by:** `src/process_runtime/models/__init__.py` (the `UnitModel` contract).

## 2026-09-19 — The declaration is transcribed twice, on purpose

**Question.** Should a model's manifest be generated by loading P01's declared YAML?

**Choice: no.** Each model re-states its ports, equations, dependencies and accumulation kinds in
Python, and `tests/test_k02_unit_models.py` compares the two transcriptions field by field.
Generating one from the other would make the comparison vacuous — the failure mode this project
keeps finding in its own tests.

**Cost:** the declarations are duplicated text. That *is* the mechanism.

## 2026-09-19 — Causal sensitivities stay `unavailable`

**Question.** P01 declared every derivative `unavailable` because nothing was implemented. Now
that the models exist, which entries can be upgraded?

**Choice: none of them.** K02 exposes residual rows (differentiated by CasADi through the K01
adapter, declared as a new `residuals / free_variables / ad` entry) and a causal evaluator that
returns values. No sensitivity interface exists, so `d(recycle.state.n)/d(inlet.state.n)` is still
unavailable even though the splitter is linear and the answer is literally `r`. Declaring
`analytic` would name a capability no caller can reach.

**Rejected:** marking the linear models `analytic` because the arithmetic is obvious.

## 2026-09-19 — A float route for rows, which is not a backend

**Question.** How is "`HEAT-mole` at `n_in = 1`, `n_out = 0.5` returns `+0.5` exactly" checked?

**Choice:** `process_runtime.compile.reference` evaluates a `ProblemSpec`'s rows on plain floats
through the `Algebra` protocol. Values only — no derivatives, no sparsity, no `CompiledProblem`,
no identity hashes — so ADR 0003 and its D5.7 backend-isolation rule are untouched. Going through
a compile, a dense assembly and a CSC extraction to check `+0.5` would test the compiler instead.

The same module gives the adapter an independent witness: both routes must agree on every row.
Both call the same `build`, so this checks *plumbing* (variable order, block wiring, parameter
binding) and explicitly not the equations.

## 2026-09-20 — The heater's two-phase outlet is lifted, not solved inside a block

**Question.** `HEAT-duty` needs the enthalpy of the heater outlet, which is two-phase in three of
the five registered variants. Where does that phase split live?

**Choice: lift it into variables**, following the formulation Fable already fixed for P02 in
`docs/derivations/P02-composition-spec.md` — `v_i`, `l_i`, `V`, `L` as variables with
`eq_i = v_i L - K_i l_i V`. Plan §4.2 requires the heater and the flash to share one TP-state
kernel, and the flash's split is lifted, so the heater's is too. The lifted variables are named
after the **stream**, not the unit, so the unit that produces a two-phase stream and the unit that
reads it refer to the same variables and the same property blocks.

**Rejected:** an opaque `PropertyBlock` that runs an inner Rachford-Rice solve and returns the
implicit derivative of blueprint §5.1. That keeps the row count at the 21 the manifests declare,
but it puts a Newton solve inside every residual evaluation and gives a one-sided derivative at
the phase boundary — and blueprint §5.1 itself warns that "a derivative through an incompletely
converged algorithm is not automatically the derivative of the intended model".

**Why the row count is not a problem.** ADR 0008 D3.5's 21 rows are *manifest declarations*, and
assertion M3 counts the manifests (`tests/test_adr_0008_transient_readiness.py:255`), not the
assembled system. D4.4 explicitly contemplates rows the assembly authors itself and requires them
to be declared `algebraic` explicitly, which the five lifting rows are.

**One orientation trap.** P02's `bal_i` and `energy` rows are written *outflow minus inflow*. ADR
0008 D3.3 later reversed every balance row. The manifest statements are what K02 implements, so
the rows here are the negation of P02's.

**Carried by:** `src/process_runtime/models/syn001/tp_state.py`.

## 2026-09-20 — A stream id must be a plain identifier

CasADi names a `Callback` with the block id and accepts only a letter followed by letters, digits
and non-consecutive underscores — `H.S2.liquid` is refused. Sanitizing silently would let two
stream ids collapse onto one block, so `tp_state` refuses a stream id that cannot name a block
instead. Found by a test, not by reading the CasADi source.

## 2026-09-20 — The mixer gates on enthalpy, not on a phase label

**The finding.** The registered SYN-001 recycle is the flash's own liquid at the flash
temperature, so it sits exactly on its bubble point. In double precision `sum_i z_i K_i` evaluates
to **1.0000000000000002** — two ulps over — and the provider, following its registered
classification order, calls the stream `TWO_PHASE` with a vapour fraction of **1.3e-17**. Fable's
20-digit reference registers the same stream as `recycle_phase_signature: LIQUID`, and its
`H_recycle_W` is the liquid enthalpy.

Both are right at their own precision. The consequence is that a mixer which gates its inlets on
the phase *label* rejects the **nominal registered variant**.

**Choice.** Admissibility is checked on the quantity that can produce a wrong number: a stream may
be treated as liquid when its liquid enthalpy differs from its true TP-state enthalpy by less than
the energy tolerance **ADR 0001 D6 registers for SYN-001** (`1e-5 W + 1e-8 x 1e5 W`). The
saturated recycle misses by about 6e-13 W and passes; an equimolar feed at 347.45 K, barely above
its 347.44118 K bubble point, misses by 29.4 W and does not. The inlet enthalpies then used are
the liquid ones, which is what `MIX-energy`'s blocks compute and what the reference records — so
the row and the evaluator describe the same function.

**Rejected:** loosening the phase-label comparison with an epsilon on the vapour fraction. That
invents a number for a phase boundary; this uses a registered one, on the quantity that matters.

**Rejected:** using the true two-phase enthalpy for the inlets. More accurate in isolation, but it
would make the evaluator disagree with `MIX-energy`'s single-phase blocks by 6e-13 W at the
saturated boundary, and "residual and evaluator describe the same function" is worth more than
6e-13 W.

**Hands forward to K03.** Its phase-attempt controller meets this same boundary, and the
classification there is a decision about which active set to try, not about an enthalpy. Pinned by
`tests/test_k02_mixer.py::test_the_registered_recycle_is_saturated_and_the_label_disagrees_with_the_reference`.

## 2026-09-20 — The tear map is exactly affine along the ray through its fixed point

Measured while looking for an anti-vacuity check, then derived. For a tear `t = s t*`,

    R(s t*) = G(s t*) - s t* = (1 - r)(1 - s) t*,

exactly — worst relative deviation **1.1e-14** over four registered variants and eight scale
factors from `s = 0` to `s = 4`.

**Why.** `t*` is `r L* x` where `x` is the flash *liquid* composition, a saturated liquid at the
flash state. Adding material of exactly that composition to a two-phase mixture at the same
temperature and pressure adds nothing that can vaporize: the vapour phase is untouched, `x` and
`y` are unchanged, and the liquid grows by exactly the amount added. So `V(s) = V*`, `x(s) = x`,
`L(s) = L(0) + s r L*`; at the fixed point `L(0) = (1 - r) L*`, giving `L(s) = L*[(1 - r) + s r]`
and the relation above.

It is the same physics as the mixer's saturated-recycle finding, seen from the other side: the
relation holds *because* the recycle sits exactly on its bubble point.

**Why it is in the suite.** It exercises the whole flowsheet at eight *non-solution* states per
variant against a closed form, where the fixed-point test gives one state and the answer zero. A
splitter that swapped its outlets, or a unit that renormalized a composition, satisfies the fixed
point and fails this.

## 2026-09-20 — The registered tear initializer is outside the v0.0 mixer's domain

**A finding for K03, recorded rather than worked around.** Derivation §9 registers
`recycle_i = r F_i` as the tear initializer, and plan §3.2 fixes that stream's temperature at the
flash specification. At r = 0.5 that is an **equimolar** stream at **360 K** — and the equimolar
mixture boils at 347.44 K, so the initializer is two-phase (`sum z_i K_i` = 1.3837, the
reference's own `sum_zK_fresh`).

The v0.0 mixer refuses a two-phase inlet, correctly: its closure cannot account for the latent
heat. So a damped Newton started at the registered initializer fails on its **first** residual
evaluation. The converged recycle is not equimolar — it is the lighter-depleted saturated liquid
(0.298, 0.546, 0.795) — and the mixer accepts that.

This is K03's to solve (blueprint §7.4 initialization and homotopy, §7.1 "feasible starting
attempts"). K02's job was to find it and say so, not to loosen the mixer until the registered
initializer happened to work. Pinned by
`tests/test_k02_flowsheet.py::test_the_registered_tear_initializer_is_outside_the_v0_0_mixer_domain`.

## 2026-09-20 — The property package reaches identity through the label

ADR 0008 D4.1 left a gap K02 inherited: the thirteen SYN-001 physical constants were hashed by
nothing, so two flowsheets over different property data would share an identity. They cannot
reach `constants_sha256`, which hashes the pinned inputs and those are floats.

**Choice:** the flowsheet label names the provider — its id and twelve hex digits of each of its
two declared hashes — so the constants reach identity through `model_version`. ADR 0002 D2.7
already requires the label to change whenever the equation set does, and the provider *is* part
of the equations. Ninety-six bits is a distinguishing name, not a cryptographic claim; the full
hashes stay in `PropertyCapabilities`.

Tested both ways: a provider declaring different data gives a different `model_version` with the
*same* structure digest, and a different recycle ratio gives the same structure digest with a
different `constants_sha256`.

## 2026-09-20 — The Fable review of K02, and what it changed

Brief: `docs/briefs/K02-unit-models-review.md`. Note: `docs/reviews/K02-review.md`. Three
must-fixes, all three verified independently before acting, all three real. The measured numerics
— orientation, D4.3, duties, tear residual, recycle invariance, the affine relation — were found
sound and unchanged.

**A method failure of my own, first.** My initial "confirmation" of must-fix M1 applied a
`str.replace` whose pattern no longer matched the formatted source, so the mutation was never
written and the run proved nothing. I then repeated the same error confirming the *fix*. Both runs
reported a clean suite and both were empty. Every mutation script now asserts that the
substitution actually landed before it runs anything, and the M1 finding was re-confirmed properly
in a detached worktree at the pre-fix commit: **1003 of 1003 passed with the K-value removed.**

### M1 — the heater's lifted equilibrium rows were never evaluated at a two-phase state

Every reference-state test used the nominal variant, where the heater outlet is single-phase,
`S3.V` is zero, and `v_i L - K_i l_i V` is identically zero **for any K at all**. Dropping the
K-value entirely passed the whole suite.

Fixed by parametrising the assembled-rows test over all five variants, using the reference's own
`heater_outlet_vapor_fraction`, `heater_outlet_x` and `heater_outlet_y` — three of the five have a
two-phase heater outlet — plus a sign test and a closed-form K-value test on the heater's row.
Four tests now fail on that mutation.

Two smaller things fell out of it. The reference writes `undefined (zero vapor flow)` rather than a
zero vector where a phase has vanished, which only appeared once the test ran on all five
variants; and the assembled-rows test had been bounding *every* row by the energy tolerance, the
loosest of the registered set, which would have let a 1e-4 mol/s component-balance error pass.
Each row is now bounded by the tolerance registered for its own unit.

### M3 — the admissibility bound was extensive, and admitted a wrong number

The criterion of the previous entry bounded the enthalpy gap in **watts**. That is an extensive
bound on an intensive question, and it passes whenever the throughput is small enough. Measured:
at 1e-8 mol/s a 45%-vapour inlet carries 3.8e-4 W of latent heat, slips under the 1.01e-3 W bound,
and the mixer returned `ok`, `LIQUID`, **outlet 330.0 K where the true liquid closure gives
393.9 K**. At nominal throughput the bound was already 2.18e-6 K, twice the registered temperature
tolerance.

Now the gap is divided by `dH/dT` — the slope the closure already queries — and compared against
ADR 0001 D6's registered **temperature** tolerance. Scale-free, registered constants only, and it
bounds the quantity a caller actually sees. The test lives in `tp_state.single_phase_admissible`
and the heater and the mixer share it, which also closes the review's S1: the heater had been
comparing phase *labels* while the mixer compared enthalpies, so it would have refused the
registered saturated recycle that the mixer admits.

Pinned from both sides by a measured case: the equimolar feed at **347.4412 K**, two hundredths of
a millikelvin above its bubble point, has an equivalent error of 2.0e-4 K — two hundred times the
registered bound and five times inside a thousandfold one. A sweep found that without it, widening
the bound by 1000 survived.

### M2 — the label carried pinned inputs

It carried `r`, the flash temperature and the heater temperature. ADR 0008 D4.1 says
`model_version` "identifies equation structure and backend form only" and that two instances from
the same structure with different specification values **share** it. Carrying them broke that,
defeated re-binding without recompilation, and overflowed ADR 0002 D2's 64-character cap at
`r = 0.123`, `T_f = 360.25`. Removed; the provider identity stays, because a different property
package *is* a different function. The label is now 43 characters.

### Should-fixes acted on

- **S2** — the bracket claim needed ideal mixing, not only a monotone `h^L`. The telescoping step
  requires `Hdot = sum_i n_i h_i^L`; an excess enthalpy term breaks it. Docstring corrected.
- **S3** — the lifted equilibrium admits the classical **trivial solutions**, and the register
  entry had confused them with the dormant stream. Measured and registered as a test: at the
  once-through variant's two-phase heater outlet, the all-liquid split leaves thirteen of fourteen
  heater rows at exactly 0.0, and a solver free to choose `Q` closes the fourteenth at a duty
  8237.85 W below the true one. Excluding it is K03's.
- **S5** — `traverse` trusted the guess's temperature and pressure. The tear is three component
  flows *because* those two are known from the flash specification, so a guess that disagrees is
  refused.
- **S7** — the registered energy tolerance is **1.01e-3 W**, not 1.001e-3: `1e-8 x 1e5` is `1e-3`.
  Corrected in the state file, the brief, the manifest generator and a test docstring. The code
  always computed it correctly; only the printed value was wrong.

### Not acted on, and why

- **S4**, six row builders duplicated two to four times. Real, and M1 did hide behind it. A
  consolidation changes no numerics but touches every unit, and CLAUDE.md forbids changing
  numerics while changing structure, so it belongs in its own commit proved bit-identical. Left
  for K03's opening or a dedicated pass, and recorded here so it is not lost.
- **Finding 1**, the registered tear initializer. The reviewer's call is to amend derivation §9 to
  register `t⁰ = G(0)`, and said they would apply it as a separate Fable commit. That is a change
  to a Fable-authored derivation and is not mine to make.
