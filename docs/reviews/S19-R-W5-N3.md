## Q2: refusal order

The proof is structural:
- The helper body is the parent's ladder, token for token, with `return None` appended.
- The caller's only earlier statement is `del context`, which came first at the parent too.
- Every rung returns `_refused(...)`, a non-None `PropertyResult`, so `is not None` passes the first rung that
  fires, with the same code and the same f-string operands (`undeclared[0]`, `unknown`, `len(state.n)`,
  `COMPONENTS`, `request.phase`, `PROVIDER_ID`, `outside`).
- No rung reads anything the caller sets.

The harness's cross product (2 phases x 3 property sets x 4 derivative sets x the malformed and dormant states)
exercises requests that hit up to four rungs at once, and the dump is equal. The ladder is lifted whole. The root
guards stay inline because they need `mix` and `z`, so this is not the playbook's "peel rung by rung" case.
