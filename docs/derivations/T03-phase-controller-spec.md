## 1. Scope, authority, and what is out of scope

**What T03 delivers.** One phase-attempt contract for both paths on which phases arise — the tear path, where the residual selects phases itself (K03 §9), and the lifted EO path, where phases are variables and the controller selects them (T02 §6.3). It states, per attempt, which phase set is frozen, how a phase change is observed on a trial, how a phase appears during an attempt and how one disappears, which point the next attempt opens from, what is checked before it opens, what is rebuilt, when a restart is refused as cycling or budget, and what a returned root carries so that two roots can be told apart. It re-registers T02's two expected failures as successes with closed-form and twin-derived expectations, and registers three new phase cases (one of them an honest failure), two synthetic tear seeds, and the multiple-root cases.

**The brief's eight questions, and where each is answered.**

## 2. The verdict, in one paragraph

An attempt freezes a signature — one regime per phase-selecting unit, from the lattice `LIQUID — TWO_PHASE — VAPOR` — and nothing inside it changes that set or the equations it selects. A trial whose regime differs is rejected `phase_update_required` and halved; on the tear path the traversal reports the regime, on the lifted path K03 §8.2's admissibility check screens every trial of a single-phase unit and a flagged trial asks the kernel. Two consecutive iterations at the wall, or a stall with a wall in the window, close the attempt (K03 §9.3, unchanged), and the next attempt opens from the **largest-α phase-rejected trial of the last such line search whose regime is adjacent** to the frozen one, else from the largest-α one. On the lifted path a phase disappears only when an attempt ends **`BOUND_BLOCKED` on one of its variables** — a landing alone is an overshoot, not a disappearance — and T02's closure conversions (an inadmissible converged root; a failed attempt the kernel disagrees with) are kept. Before an attempt opens, six compatibility checks run and a failure is `CHECKPOINT_INCOMPATIBLE`; every attempt gets its own evaluation context, its own problem and a recorded structural Jacobian pattern. A signature is still attempted at most once per solve, at most five attempts. A converged, admissible solve carries its attempt history and a root fingerprint compared at `δ_root = 1e-4` in scaled coordinates, and claims neither uniqueness nor dynamic stability. On the A02 family this turns T02's two cycling failures into two-attempt successes (LIQUID → TWO_PHASE, 2 + 5 and 2 + 4 core iterations), adds a vapour-side appearance and a genuine disappearance, and registers one guess near the dew point that still cycles — honestly, because the bound rule cannot tell a Newton overshoot two steps deep from a phase leaving. Each of the three new rules is load-bearing: removing any one of them turns both re-registered successes back into `ACTIVE_SET_CYCLING`.

## 4. The contract (normative; ADR 0005 D1–D8)

### 4.1 Terms

- **Phase-selecting unit.** A unit whose phase regime a solve depends on: on the tear path the units of `SolvePlan.signature_units` (T01 §9.6; for SYN-001 the flash); on the lifted path every lifted unit of the region (T02 §6.3.1).
- **Regime.** One of `LIQUID`, `TWO_PHASE`, `VAPOR`. **Signature** `σ`: the tuple `((unit, regime), …)` over the phase-selecting units in `signature_units` order. Equality is tuple equality (K03 §9.4).
- **Attempt.** One run of a core (K03 §5 Newton or T02 §5 Anderson) with a frozen signature, a frozen problem, frozen scales and one evaluation context (K03 §12.4).
- **Trial.** A point evaluated by a line search; **phase-rejected trial**: a trial whose evaluation succeeded and whose reported signature differs from the attempt's.
- **Candidates** of an attempt: its phase-rejected trials in the most recent iteration that had at least one, in the order encountered (decreasing α). This is K03 §9.3's "last line search" as `attempts.py` reads it: the most recent line search containing a phase rejection.
- **Opening state** of an attempt: the point it starts from, with the source that produced it (§4.8).

### 4.2 The signature, and what freezing it means ([A01])

For every accepted iterate, trial, residual call, Jacobian call and derivative perturbation of an attempt: the signature is the attempt's; on the lifted path the pinned variables of every single-phase unit are exactly `+0.0` and its dropped rows are absent (T02 §6.3.1); the residual is the frozen formulation's and **no call alters it** — the phase observation of §4.3 reads a trial, it never re-selects equations. The core receives one `AttemptContext` and takes every evaluation context from it (K03 §12.4). Each attempt constructs **new** `EvaluationContext` objects (field-equal on these paths, distinct objects), as `docs/interfaces-frozen.md` §1 requires ("constructs a new context after a phase restart"); K03 A28's object-identity test then distinguishes attempts, which today it does not (§16, finding 4).

### 4.3 Observing a phase change on a trial

**Tear path (unchanged).** The traversal's signature at the trial (K03 §9.1's fixed map for the flash).

**Lifted path (new).** For each unit whose frozen regime is `LIQUID` or `VAPOR`, in signature order, the **screen** evaluates K03 §8.2's check on the unit's single-phase branch at the trial: `Σ x_i K_i` of the liquid (`LIQUID`) or `Σ y_i / K_i` of the vapour (`VAPOR`), compositions from the unit's lifted variables at the trial, `K_i` at the trial's `(T, P)` of that stream, against `1 + admissibility_epsilon` (1e-12). It is the **same function** the closure check of §4.7(a) calls. A trial whose value exceeds the bound is *flagged*; for a flagged unit the kernel — the provider's TP flash of that stream's `(n, T, P)` — reports its regime. The trial's **reported signature** is the frozen one with each flagged unit's regime replaced by the kernel's. `TWO_PHASE` units are never screened (a phase leaves them by §4.6, not by a screen).

- Order of checks on a trial (K03 §5.4, unchanged): a typed non-`ok` evaluation → `invalid_trial` and no screen; then the reported signature → `phase_update_required` if it differs; then Armijo.
- A flagged unit whose kernel regime equals the frozen one is not a phase rejection (the kernel is the authority on regime; the screen only decides whether to ask it).
- A kernel refusal (non-`ok` status) makes the trial `invalid_trial` with the provider's status recorded (K03 §5.5); `error` is `EVALUATION_ERROR`.
- **The opening state is not screened.** An attempt may open at a state its own screen would reject — a disappearance restart opens wherever the bound stopped the Newton, which need not be admissible in the new regime — and reach an admissible root: T02 A21's second attempt opens with `Σ z K − 1 ≈ +1e-5`, PHS-04's with `Σ x K = 1.075 417 012 292 933`. Admissibility is what the attempt converges *to*, checked at closure (§4.7(a)); it is not a precondition.
- **Cost.** Per trial of a single-phase lifted unit: one K-value evaluation at the trial's `(T, P)` through the exact property cache. Per flagged trial: one TP flash. Registered counts on attempt 1: PHS-01 15 screened trials, 13 flagged; PHS-02 14 screened (2 refused by the domain before screening), 12 flagged; PHS-03 8 screened, 6 flagged. These calls count against `max_property_calls` like every other provider call. *Amended by the T03 implementation review, 2026-09-24:* "through the exact property cache" describes the tear path; the region path has no cache, so there the screen's calls go through the step's metered provider, uncached (*measured*: 28, 26 and 14 provider calls on PHS-01, -02, -03 — 15 + 13, 14 + 12, 8 + 6 — and none on an attempt with no single-phase unit). A refusal inside the screen — the budget's or the provider's — is a typed evaluation of the trial like the compiled residual's (`error` → `EVALUATION_ERROR`, the step then reporting `BUDGET_EXHAUSTED` from the meter; any other status → `invalid_trial`), never an exception that leaves the attempt loop (review S1).

This is blueprint §6.3's "a trial that cannot be evaluated in the fixed formulation returns a typed … `PHASE_UPDATE_REQUIRED` outcome", for the one way a single-phase lifted state fails the fixed formulation without failing its arithmetic: it is a state the phase set cannot physically hold.

**Rejection, wall, stall (K03 §9.3, verbatim, both paths).** A phase-rejected trial halves `α` like any rejection. The attempt closes **`PHASE_UPDATE_REQUIRED`** when `phase_wall_patience = 2` consecutive iterations each had a phase rejection (trigger `patience`), and is converted when its core outcome is `LINE_SEARCH_FAILED`, `STAGNATION` or `RECYCLE_STAGNATION` with the last phase rejection fewer than `stagnation_window = 5` iterations before the closing iteration (trigger `stall`).

### 4.4 The regime lattice and adjacency

`LIQUID — TWO_PHASE — VAPOR`: `TWO_PHASE` is adjacent to both single-phase regimes; `LIQUID` and `VAPOR` are **far** from each other. A signature `σ'` is **adjacent** to `σ` iff both range over the same units, every unit's regime is equal or adjacent, and at least one differs.

Why this lattice and not a set of three unordered labels: for the provider class of K03 §8.2 (finite positive K-values), the liquid region `Σ z K ≤ 1` and the vapour region `Σ z/K ≤ 1` intersect only where `K_i = 1` for every component present (Cauchy–Schwarz: `(Σ z K)(Σ z/K) ≥ (Σ z)² = 1`, with equality only for equal `K_i`), so a continuous path from a liquid state to a vapour state passes through `TWO_PHASE`. The adjacent candidate is the regime a Newton segment *enters first*; a far candidate has jumped the region the path had to cross — and in every registered double-overshoot case (PHS-01, -02, -03) the root lies in the region jumped.

### 4.5 Choosing the restart point

Among the candidates (§4.1), the **first whose reported signature is adjacent** to the attempt's; if none is, the **first** (the largest α, K03 v0.0). Ties are impossible (distinct α); the rule is deterministic and R0.

The new signature is the chosen candidate's. The opening state is the candidate's state — on the tear path its tear vector (K03 §9.3); on the lifted path its full region state with, for every unit whose regime changes, the lifted split set from the kernel at that state (the kernel's regime equals the candidate's by construction, so the split is on the new branch).

*Rejected:* the smallest-α candidate ("nearest the wall"). On the twin's scan of the A02 family (`ref…family_scan`: targets 340, 355, 358, 360, 365 K × 15 guesses from 300 to 430 K) it fails 5 of 75 runs — 355 K from 375, 377, 380, 400 and 430 K — where the largest-adjacent rule fails 2 (375 and 377 K), and it would change the restart point of K03's registered OFF-B trajectory, which the adjacent rule leaves bit for bit (every OFF-B candidate is `TWO_PHASE`). *Rejected:* K03 v0.0's largest α unconditionally — PHS-01/02 restart `VAPOR` from 389.44 K and 396.68 K, whose own wall's largest candidate is `LIQUID` again (§6.7).

### 4.6 Disappearance on the lifted path: a persistent block, not a landing

A **watched** variable of a `TWO_PHASE` unit, evaluated at the attempt's end state: each phase's total (`V`, `L`) while the stream's total `N > 0`; each phase component (`v_i`, `l_i`) while the stream's component `n_i > 0` (T02 §6.3.3's premise and exception, unchanged). Single-phase units have no watched variable: their one phase cannot leave while the stream flows, and a component landing there is the stream's own component vanishing (ADR 0001 D3.3), not a phase event.

An attempt whose core ends **`BOUND_BLOCKED`** with a watched variable in `NewtonResult.blocked_by` closes into a restart with `cause = phase_disappeared(unit, phase, variable)` — the first watched variable in `blocked_by` order — and the unit loses that phase (`TWO_PHASE → LIQUID` for vapour, `→ VAPOR` for liquid). The opening state is the end state with that phase pinned (`v = 0, V = 0, l = n, L = N`, or symmetrically; T02 §6.3.3's restart point).

**A landing is not a disappearance.** An exact landing at `α_max` (K03 §5.3) is accepted as an iterate and the attempt continues; the phase has left only if the next direction points out of the feasible set there, which is `BOUND_BLOCKED`. This supersedes T02 §6.3.3's first trigger. Reason, registered: in PHS-01 and PHS-02 the `TWO_PHASE` attempt's first step lands `S3.vap.C` on `+0.0` (`α_max = 0.683 005 540 573 936` and `0.848 058 504 137 589`), the next direction on it is positive, and the attempt converges to a two-phase root at 355 K and 360 K; under the landing rule both close `phase_disappeared` and cycle (§6.7). The nominal EO case T02 A21 is unchanged in every registered respect: its landing on `S3.vap.B` at iteration 0 is followed by `BOUND_BLOCKED` at iteration 1 (*measured*, T02 finding 10), which now closes it with the same cause, the same restart state and the same closing iteration — at the cost of one Jacobian and one factorization.

### 4.7 Appearance at closure (T02 §6.3.4, retained)

**(a)** On a core `CONVERGED`: K03 §8.2 on every lifted unit in signature order **by the branch found** — `V = 0` is judged as all-liquid and `L = 0` as all-vapour whatever the frozen regime, so a `TWO_PHASE` attempt that converged onto a trivial branch is judged too (the region's `TWO_PHASE → admissible` shortcut is a finding, §16). The first inadmissible unit gives `cause = inadmissible(stream, branch, value)`; the new regime is the kernel's at the converged state, the opening state that state with the unit's split from the kernel. All admissible → the solve is `CONVERGED`.

**(b)** Lifted path only, on a core outcome `STAGNATION`, `LINE_SEARCH_FAILED`, `BOUND_BLOCKED` (no watched variable blocked) or `BUDGET_EXHAUSTED(newton_iterations)` that §4.3's stall trigger did not take: the kernel's regime of each lifted unit at the **end state** (the last accepted iterate; T02 §6.3.4(b) says "best iterate", but the Newton core tracks none and the implementation and T02's measured A31 use the end state — §16, finding 6). The first unit that differs gives `cause = kernel_disagrees(unit, regime)` and a restart from that state with the kernel's split; none differs → the failure stands.

On the tear path neither conversion can fire (K03 §8.1: the residual selects the branch); the admissibility check still runs on the converged state and its verdict is carried.

### 4.8 The decision at attempt closure (one function, both paths)

**Precedence** — the first that applies:

| # | Core outcome and condition | Decision | Opening source |
| --- | --- | --- | --- |
| 1 | `CONVERGED` | §4.7(a): admissible → solve `CONVERGED`; else restart | `closure_projection` |
| 2 | `PHASE_UPDATE_REQUIRED` (patience) | restart by §4.5, `cause = phase_wall(patience, <changes>)` | `phase_rejected_trial` |
| 3 | `BOUND_BLOCKED`, watched variable blocked (lifted) | restart by §4.6 | `pinned_iterate` |
| 4 | `LINE_SEARCH_FAILED` / `STAGNATION` / `RECYCLE_STAGNATION`, wall within the window | restart by §4.5, `cause = phase_wall(stall, <changes>)` | `phase_rejected_trial` |
| 5 | `STAGNATION` / `LINE_SEARCH_FAILED` / `BOUND_BLOCKED` / `BUDGET_EXHAUSTED(newton_iterations)` (lifted) | §4.7(b) | `closure_projection` |
| 6 | anything else | the core outcome ends the solve (tear under `anderson`: T02 §4.4's merge edge may follow at plan level) | — |

**Restart gate**, for a restart into `σ'` after attempt `k` (0-based), in this order: (i) `k + 1 = max_attempts` → **`ATTEMPTS_EXHAUSTED`**; (ii) `σ'` already the signature of an attempt of this solve → **`ACTIVE_SET_CYCLING`** (§7); (iii) the opening checks of §5.1 → **`CHECKPOINT_INCOMPATIBLE`** on the first that fails; (iv) open attempt `k + 1` with the rebuild of §5.2. This is the order `attempts.py` and `region.py` already follow for (i)–(ii).

A terminal outcome reports the last accepted iterate, never a candidate (K03's fix recorded in `attempts.py`), and the checkpoint of the last attempt that accepted a step or converged, labelled `partial` unless the solve converged.

**One implementation.** The precedence, the selection of §4.5, the gate and the construction of the opening state are one decision function that the tear controller (`solve_with_attempts`) and the region solve both call, and one wall observer class records candidates for both. Neither path keeps its own cycle or budget check. (Today there are two controllers with two copies of the cycle rule; §17 W2.)

### 4.9 Registered constants

No solver constant is added or changed: `phase_wall_patience = 2`, `stagnation_window = 5`, `max_attempts = 5`, `step_halvings_max = 20`, `admissibility_epsilon = 1e-12` (the screen uses the closure check's own ε), `cycle_rule = no_repeated_signature`. The rule set is named by a new single-valued policy literal `SolvePolicy.phase_contract = "T03-phase-contract-v1"` (ADR 0005 D1), so a replay under a policy without it is refused rather than silently run under different rules. One comparison constant is added outside the solver: `δ_root = 1e-4` (§8.3).

### 4.10 What is recorded

- `attempt_opened` (existing kind): `state_sha256` = the opening free vector in the attempt's variable order, **non-empty on both paths** (the region writes `""` today); `alpha` (existing nullable field) = the chosen candidate's α when the source is `phase_rejected_trial`, else `null`; `message` = `initial` for attempt 0, otherwise `phase_update(<cause>)`.
- `<cause>` grammar: `phase_wall(<trigger>, <unit>:<from>-><to>[, …])` with `<trigger> ∈ {patience, stall}`; `phase_disappeared(<unit>, <phase>, <variable>)`; `inadmissible(<stream>, <branch>, <value>)` (`<value>` as Python `repr`); `kernel_disagrees(<unit>, <regime>)`.
- `attempt_closed` records **what the core did** (its own outcome and message, K03 §5); the controller's decision is on the next `attempt_opened`, or on `solve_closed` when terminal: `active_set_cycling(<signature>; <cause>)` with `<signature>` as `unit:regime,unit:regime`, or `checkpoint_incompatible(<check>, <detail>)`. This moves ADR 0009 D3's structured phase reasons from `attempt_closed` to `attempt_opened` — under §4.6 the disappearance's core outcome is `BOUND_BLOCKED`, and an `attempt_closed` must say what the numerics did.
- A lifted-path `trial` event carries the reported signature (K03 §12.3's existing meaning).
- `AttemptContext.opened_from` keeps the meaning the implementation gives it: the checkpoint of the attempt that closed into this one (`test_k03_schemas.py` asserts its old signature and `partial` label). K03 A29's text, which says the restart point's hash equals `opened_from.state_sha256`, contradicts it; the restart point is `attempt_opened.state_sha256` (§16, finding 3). *(Review note: K03 §12.5 writes no checkpoint for an attempt that accepted no step, so after such an attempt `opened_from` is the most recent earlier checkpoint.)*
- *Amended by the T03 implementation review (S4), 2026-09-24.* **No measured float in an R0 string.** The messages and causes above are R0 (A23 compares them byte for byte across the CI pair), and a float computed from a solved state may differ in its last bits between platforms. So the R0 forms are `inadmissible(<stream>, <branch>)` and `checkpoint_incompatible(<check>, <variable or field>)`; the admissibility value and the offending number go to non-R0 records (`RegionAttempt`, the failure bundle's observations). This supersedes the `<value>` of the grammar above and of ADR 0009 D3 as amended by ADR 0005 D8.
- The region solve records no `solve_closed` of its own: its terminal decision is `RegionResult.message` in this grammar, which the plan executor's `solve_closed` carries in a plan run (review, brief decision 6: accepted).

## 5. Checkpoint compatibility and the sparsity rebuild

### 5.1 The opening checks (ADR 0005 D6)

Before attempt `k + 1` opens from a state `s`, all six hold or the solve ends **`CHECKPOINT_INCOMPATIBLE`** naming the first that fails:

| Check | Holds iff | Tear path | Lifted path |
| --- | --- | --- | --- |
| `identity` | `s` was evaluated under the attempt's `model_version` and `constants_sha256` | ✓ | ✓ |
| `step` | `s.step_index` equals the current plan step's (`null` for the bare controller) | ✓ | ✓ |
| `scale_segment` | equal to the new attempt's (0 in v0.1) | ✓ | ✓ |
| `coverage` | a finite value for every free variable of the new attempt (lifted: every region variable) | ✓ | ✓ |
| `active_set` | the candidate's reported signature equals `σ'` (tear) / every variable `σ'` pins is exactly `+0.0`, sign bit clear (lifted) | ✓ | ✓ |
| `bounds` | every bounded free variable at or above its lower bound | ✓ | ✓ |

A refusal records `solve_closed` with the outcome and `checkpoint_incompatible(<check>, <detail>)`, opens no attempt (no `attempt_opened`, no residual or Jacobian call after the decision), carries the last checkpoint as `partial`, and issues no certificate. Taxonomy (`verify/failure.py`): class `homotopy/PTC/active-set stalls` — the controller that produced it — with the action overridden to `report_defect` (ADR 0009 D6's pattern): no registered path produces an incompatible state, so one that appears is a defect, and `supply_initial_guess` would point the reader at the wrong object.

The checks are cheap invariants on internal restarts. They exist so that the first external source of an opening state — a compatible warm start, K03 §10.1 source 2, absent in v0.1 — enters through a check that already has a typed refusal and tests. **Registered bites** are constructed (A16): an opening state with `S3.vap.A = 1e-3` under a `LIQUID` signature (`active_set`), one with `scale_segment = 1` (`scale_segment`), one evaluated under another `model_version` (`identity`), one with `S3.liq.B = −1e-9` (`bounds`).

### 5.2 What is rebuilt when the phase set changes, and how that is evidenced

## 7. The general signature rule and the cycle rule

**Decision: no recurrence in v0.1.** `cycle_rule` stays `no_repeated_signature`: a restart into a signature this solve has already attempted is `ACTIVE_SET_CYCLING`. The signature itself is generalized only in its domain — every phase-selecting unit of `signature_units` in plan order, on both paths (§4.1) — and in the lattice that orders it (§4.4).

**Why.** Register R-012 records "a session raising the cycle rule to allow repeats without ADV-01 evidence" as the failure to watch for, and K03 Q3 says to raise the patience before changing the cycle rule. T03 now has the evidence R-012 asked for, and it points the other way: PHS-05 is the one registered case where the rule bites on a solvable problem, and neither natural recurrence rule rescues it (generator-checked): **count-based** recurrence (a signature may recur, bounded only by `max_attempts`) ping-pongs `TWO_PHASE, LIQUID, TWO_PHASE, LIQUID, TWO_PHASE` into `ATTEMPTS_EXHAUSTED` (the adjacent candidate of each `LIQUID` wall lies near the dew point, from which the two-phase Newton overshoots again); **merit-progress** recurrence (recur only if the opening merit is strictly below the previous opening's) is refused at once — the second `TWO_PHASE` opening, at 377.505 K, has merit 1.352 against 0.659 at the first (`ref…ablations`) — and ends `ACTIVE_SET_CYCLING`. The defect PHS-05 exposes is in the disappearance premise far from a root (§4.6, §13), not in the cycle rule; a rule that lets signatures recur would add a lever with no case it helps and a new way to spend five attempts. The case is registered as an expected failure and handed to T04: the failure is a Newton step from 375 K far larger than the region in which its linearization of the lifted split holds, which is a globalization question, not a phase-logic one.

"Hysteresis may stabilize iteration but cannot change final physical acceptance conditions" (blueprint §7.6): the wall patience and the persistent-block rule are hysteresis on iteration; the final acceptance — K03 §8.2 on the converged state, by branch found — is unchanged.

### 8.3 Comparing two roots, and why `δ_root = 1e-4`

`same_root(f_a, x_a, f_b, x_b, S) ∈ {SAME, DISTINCT, NOT_COMPARABLE}`: **`NOT_COMPARABLE`** if `policy`, `model_version`, `constants_sha256` or `variable_ids_sha256` differ (a root of another problem is neither the same nor a different root of this one); otherwise **`DISTINCT`** if `branch_found` differs or `max_i |x_a,i − x_b,i| / S_i > δ_root`; otherwise **`SAME`**. `S` are the plan's column scales by id (the certificate's `transformations.scales.column`; 3 mol/s for the manufactured tears).

*Amended by the T03 implementation review (S3), 2026-09-24.* The comparison reads states, so it must be told which states: `same_root` takes the variable ids, and **refuses** (a typed error, never one of the three verdicts) when either state's ADR 0008 D2 hash over those ids is not its fingerprint's `full_state_sha256`, when the ids' hash is not `variable_ids_sha256`, or when `S` lacks a positive scale for any id. The maximum runs over the ids, never over whatever keys `S` happens to hold. (*Measured* before the amendment: empty `S` returned `SAME` for REC-05's two roots, 0.963 apart; a fingerprint paired with the other root's state returned `SAME`.)

Two converged states of one root differ by at most twice the first-order solution-error bound `b̂ = ‖(I − G′)⁻¹‖∞ τ̂`. ## 9. `role: free` without a value (T02 review N9)

**T03 owns it.** The A02 cases differ from each other only in their guess, and a freed variable with no guess is the degenerate member of the family whose restarts T03 specifies; leaving it silent is exactly the "silence reads as success" path rule 5 forbids, and each package that leaves it extends its life. Rule (T02 §7.5, made binding): the binding frees the column whether or not a `value` is given (the role is `free`); at the region's initializer chain the absent user guess is an `initializer_rejected` event with message `missing_initial_guess(<variable id>)`, no later source exists for a temperature (K03 §4.1), and the solve ends **`INITIALIZATION_FAILED`** with that message. Checkable (A24): the registered case `SYN-001-A02-360-no-guess` (the A02-360 revision with the `value` removed) builds the A02 plan (its `solve_eo` step lists `S3.T` in `adjusted_variables` — the column was not silently kept fixed), opens no attempt, evaluates no Jacobian, and ends `INITIALIZATION_FAILED` naming `S3.T`; no `CONVERGED` appears anywhere in its trace.

*Amended by the T03 implementation review (M2), 2026-09-24.* The refusal holds **by construction, not by the caller's care**: a missing guess is part of what the plan records for its region step, so the executor refuses from the plan it runs and no caller can omit it; the binding never stands a value in for the missing guess that a solve could start from, and a `role: free` specification without a value binds (or is refused with a typed reason) on **every** coordinate the binding can free, never with an exception. (*Measured* before the amendment: the no-guess revision run through `execute_plan` without its opt-in `missing_guesses` argument is `CONVERGED` at 360 K from the flowsheet's default 350 K recorded as a `user_guess`; `role: free` without a value on the flash temperature raises `ValueError`.)

## 13. What this specification does not establish

- **Correctness of any solver.** It registers what a correct implementation of the contract must produce. The twin is the contract simulated a second time on an exact reduction of the region; its agreement with T02's measured implementation (§6.8) is evidence that the reduction is right, not a test of the new code.
- **That the contract converges wherever a root exists.** PHS-05 is a registered counterexample on an ordinary guess, and the A02 scan (75 runs) found one more (377 K). **The bound-driven disappearance premise holds at roots, not at Newton iterates far from them**; the persistent-block rule filters a one-step overshoot (PHS-01/02), not a two-step one (PHS-05). T04.
- **Recurrence of a signature.** Not permitted; §7 says why and what would reopen it.
- **Phase changes of more than one lifted unit at once, or of the flash on the lifted path.** The rules are stated for any number of units; no registered case changes the flash's regime in a region or two units in one restart.
- **A single-phase unit whose component vanishes from the stream** (ADR 0001 D3.3), **a provider whose K-values vanish or diverge**, a **saturated lifted stream** (roots within `admissibility_epsilon` of a phase boundary), a **narrow-band** mixture where even the adjacent candidate is absent (only PHS-SYN-2's synthetic): rules stated, not exercised on physics.
- **Root completeness, uniqueness, thermodynamic stability beyond K03 §8.2, dynamic stability.** `claims` say `NOT_ASSESSED`; no root search is run. Two roots within `δ_root` are reported `SAME`; a fingerprint cannot separate nearly degenerate steady states (a turning point), and **REC-05's basin boundaries are finer than double precision resolves** (T02 *measured* 1.05 t* → `t*` against the twin's `S1`).
- **Warm starts across runs, and continuation history.** The opening checks are ready for an external checkpoint; none exists in v0.1. Continuation is T04's.
- **The cost of the screen at size.** Counts are registered on SYN-001; nothing is measured about a plant.
- **Empirical validity** of anything (SYN-001 and REC-05 are synthetic) and **human numerical or process-modeling review** (`review.*` stay `pending`).

## 16. Findings about the brief, the plan, the ADRs and the earlier specifications

1. **T02 §6.3.3's landing trigger is wrong on its own family.** A landing is a Newton overshoot as often as a phase leaving: PHS-01/02 land `S3.vap.C` on the way to two-phase roots. Replaced by the persistent block (§4.6); A21's registered numbers survive because its landing is followed by a block (*measured*, T02 finding 10). Register R-025 records "a phase leaves when any of its lifted variables lands on its bound" and "appears only at closure"; both are reversed by R-028.
2. **T02 §6.3's "no per-trial kernel test" was right about the kernel and wrong about the screen.** A verdict that changes with every trial must not *steer* one — and none does: the screen only *rejects*, and K03 §9.3's patience decides whether the rejections mean a wall.
3. **K03 A29's text contradicts the implementation.** It says the restart point's hash equals `opened_from.state_sha256`; the implementation (and `test_k03_schemas.py`) makes `opened_from` the closing attempt's checkpoint and puts the restart point on `attempt_opened.state_sha256`. The implementation's meaning is kept (§4.10); K03 A29 should be read with `attempt_opened.state_sha256`.
4. **Both controllers reuse one `EvaluationContext` object across attempts**, contrary to `interfaces-frozen.md` §1; K03 A28's object-identity test is therefore vacuous across attempts. Fixed by §4.2.
5. **The region writes `attempt_opened.state_sha256 = ""`** and records no `attempt_closed` for its conversions; the phase reasons ADR 0009 D3 places on `attempt_closed` live only in `RegionAttempt.reason`. §4.10 fixes where each fact is recorded.
6. **T02 §6.3.4(b) says "best iterate"; the implementation and T02's measured A31 use the end state** (the Newton core tracks no best iterate). §4.7(b) says end state.
7. **The region's admissibility check returns "admissible" for any `TWO_PHASE` attempt**, where K03 §8.2 judges by the branch found; a `TWO_PHASE` attempt converged onto a trivial branch would pass unchecked. §4.7(a) restores K03 §8.2.
8. **T02 §7.6's "measured 4" for `SYN-001-A02-355`** was the prototype's; the implementation measures 3, as the T02 manifest records and the twin reproduces.
9. **The two controllers keep two copies of the cycle rule** (`attempts.py`, `region.py`). §4.8 makes it one function (W2).
10. **K03 Q3 asked for ADV-01 evidence before touching the cycle rule;** T03 is that evidence and it supports keeping the rule (§7).

No change to the blueprint, the plan or ADR 0001–0004, 0006–0008 is required. ADR 0009 D3's placement of the phase reasons is amended by ADR 0005 (§4.10).
