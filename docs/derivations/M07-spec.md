## 0. The answer, in one paragraph

The journey takes **one decision**, the reactor-inlet temperature T_in of `C1-LOOP-M02-v1` (SPEC-S3-T, box
[653.15, 693.15] K, objective `c1-obj-nh3-liquid-v1` = liquid NH₃ product, purge 0.02), through four rungs of reactor
fidelity: **R0** the synthetic stand-in (fixed per-pass conversion, no temperature rise) on a nine-point grid;
**R1** the PyMRM reactor v3 (M02) on the same grid; **R2** the M04 surrogate, which is **not promotable** (M04's real
outcome, R-364), so R2 records that verdict and evaluates nothing; **R3** M05's trust-region study on the parent
(stage A skipped, `surrogate_not_promoted`). Each adjacent pair of decisions is compared by the **parent's** objective
at both decisions against the parent's noise floors (fidelity-effect class FE), the refined decision is checked against
the parent grid (truth check TC-1), and every decision carries its bound activity, constraints, uncertainty and compute
cost. W25 is **met** when the journey's record and report state all of that, honestly, reproducibly — whatever the
decision turns out to be. Budget exhausted, surrogate not promotable, an indifferent rung and a bound-active decision
are outcomes, not failures. The 0.2.0 gate is a second registry entry `v0.2-gate-v1` in `scripts/v0_2_gate.py` that
claims all seventeen gates and is judged at its own candidate.

### 4.3 The grid

Nine decimal literals 653.15 + 5k K, k = 0…8: 653.15, 658.15, …, 693.15. The nominal 673.15 K is k = 4. The end points
are the box bounds (bound activity `BOUND_LOWER`, `BOUND_UPPER`); the seven inner points are `INTERIOR` (GC-GRID-5).
Each grid point edits SPEC-S3-T of the case file in memory to the binary64 value of its literal, canonicalizes, and
solves through `run_revision_session` (the route the document selects, `revision_coupled`) without committing — the
same procedure as M05's P1 (§7.4 there). *Why nine:* 5 K spacing is ten times δ_T, cheap enough for R1 (§4.5), and
puts the nominal and both bounds on the grid so the R0→R1 pair compares parent values at grid points only.

### 4.4 Rules (implemented in `m07_reference.py`; the build lane's `scripts/m07_journey.py` implements them again)

All J are in mol/s. "Verified" means outcome `CONVERGED` and certificate `VERIFIED` (M05 P1).

**4.4.1 Rung decision.** Over a rung's grid points:
- `INCOMPLETE` if any grid point is not verified; decision = the best verified point, or none if none is verified.
- otherwise `INDIFFERENT` if max J − min J ≤ 10⁻¹² · max |J|; decision = u₀ = 673.15 K (the simple model gives no
  reason to move);
- otherwise `DECIDED`; decision = the grid point with the largest J, an exact tie going to the lowest T.

*Tolerance 10⁻¹²:* R0's measured spread is 1.19 × 10⁻¹⁶ (F2), so the tolerance sits 8 × 10³ above the floor
(GC-R0-1 requires ≥ 10³); fixture r-02 tilts J by 8 × 10⁻¹¹ end to end and must read `DECIDED` (GC-RUNG-3 requires the
tilt ≥ 10 × the tolerance). It is a rung-level statement of structural flatness, not a resolution statement; resolution
is §4.4.2.

**4.4.2 Noise floor and indifference set.** For each R1 grid point k, e_k is M05's noise floor (M05 §7.4):
e_k = 2(|∂J/∂X̂|·ΔX_k + |∂J/∂ΔT̂|·ΔT_k), achieved coupling residuals from the run's `EXT-COUPLING` checks, inner-solve
central differences h_X = 10⁻⁴, h_T = 10⁻² K (four inner solves, no reactor call). The build lane calls M05's
implementation of that formula; it does not re-implement it. The **indifference set** is the ascending list of verified
grid T_k with J_k ≥ J_best − (e_k + e_best). It is R1's uncertainty statement: "on the grid, the parent cannot tell
these temperatures apart".

**4.4.3 Before/after pairs.** Two pairs are compared: **P01** = (R0 decision → R1 decision) and **P13** = (R1 decision →
R3 candidate T*). For each, j_before and j_after are **parent** values at t_before and t_after with their noise floors:
for P01 both are R1 grid points (673.15 K is on the grid); for P13 j_after = J* and e* from M05's P1 targeted check and
noise floor at T*. A pair whose t_after does not exist (R1 has no verified point; R3 has no candidate), or whose
parent value at t_before or t_after is not verified (M05 P1 failed, or the grid point failed), has t_after = null and
is `FE_NOT_DETERMINED`; the record states which value is missing. A parent value without its noise floor is not
determined either [A1.1].

**4.4.4 Fidelity-effect class**, with ε = e_before + e_after and Δj = j_after − j_before, in this precedence:
1. `FE_NOT_DETERMINED` if t_after is null;
2. `FE_WORSE` if Δj < −ε;
3. `FE_UNCHANGED` if |t_after − t_before| ≤ δ_T;
4. `FE_CHANGED` if Δj > ε;
5. `FE_WITHIN_RESOLUTION` otherwise (the decision moved, the parent cannot tell the gain from its noise).

Boundaries are inclusive as written (fixtures fe-02, fe-04, fe-06, fe-08 sit exactly on them). `FE_CHANGED` is the
blueprint's "measured effect of fidelity on the decision"; the others are its honest absence.

**4.4.5 Truth check TC-1** (the refined decision against the parent grid): with B the best verified R1 grid point,
`TC1_HOLDS` iff J* ≥ J_B − (e* + e_B); else `TC1_CONTRADICTED`. `TC1_NO_GRID` if R1 has no verified point;
`TC1_NOT_APPLICABLE` if R3 has no candidate. The record carries B's T. Missing values and noise floors: [A1.1].

**4.4.6 Bound activity** [A2.1: the tolerance is δ_T]. `BOUND_LOWER` if |T − 653.15|/20 ≤ 10⁻⁶, `BOUND_UPPER` if |T − 693.15|/20 ≤ 10⁻⁶, else
`INTERIOR` (M05 §7.4's 10⁻⁶ scaled; half-width 20 K, so 2 × 10⁻⁵ K). A bound-active decision carries the bound phrase
(§6.3) verbatim.

**4.4.7 The journey's decision.** R3's T* if R3's candidate status is `PARENT_LOCAL_EVIDENCE` and TC-1 holds; otherwise
the best verified R1 grid point, labelled `grid_only` with the reason (R3's status, or `TC1_CONTRADICTED`); otherwise
none (`INSUFFICIENT_EVIDENCE`). The journey never reports a decision from R0 or R2. *The grid-only decision is R1's rung
decision, and the reason when R3's status is `PARENT_LOCAL_EVIDENCE` is TC-1's outcome [A1.8].*

### 4.5 Budget `M07-budget-v1` and stop rule

| Rung | Cold reactor experiments | Wall | Basis |
| --- | --- | --- | --- |
| R0 | 0 | 600 s | in process |
| R1 | 60 | 5400 s | ≥ 1.5 × (9 points × F3's worst 4 experiments, 361.5 s): 54 and 4880 s (GC-COST-1) |
| R2 | 0 (surrogate only; its grid parent values are R1's) | 1200 s | |
| R3 | 400 | 14400 s | M05-budget-v1 REAL (N-F3); M05 enforces it |
| Journey | 460 | 21600 s (6 h) | GC-BUDGET-1 |

Each rung checks its budget **before** each evaluation; a rung that would exceed it stops with `BUDGET_EXHAUSTED`,
records what it has, and the journey continues with the next rung on the evidence it has (blueprint §14.4). Store hits
cost no experiment. A real evaluation runs 25–45 s, up to 150 s under load; the budget is generous by design, and
exhausting it is a result to report, not to retry. *The estimate behind "would exceed", the evaluation order and `check`'s
re-derivation: [A1.2]. What a cold reactor experiment is: [A1.4].*

### 4.6 Execution, carry, and refusal

- **One script, no new operation.** `scripts/m07_journey.py {run,check,replay,render}` composes existing application
  calls (`run_revision_session`, the experiment store, M05's study entry point). **No job operation is added** (M05
  N-F7 deferred it to M07; DECISION in R-336): an operation would extend a frozen interface for one script's benefit.
- **Carry by identity** [A1.6; A2.2: `carry.r3_files` and `carry.journey_files`]. R3 consumes M05's committed REAL study record when the *determining files* (registration
  `carry.journey_files`: `src/openflowsheet/**`, `benchmarks/m02/**`, `benchmarks/m04/**` (R2's verdict), `benchmarks/m05/**`,
  `requirements.lock`, the reactor environment lock) are byte-equal between M05's run commit and the journey commit J;
  otherwise it re-runs M05's study at J. The same rule carries the journey from J to the RC commit C (RC step 15).
- **Refusal is a result.** Without the reactor environment, R1 and R3 report `UNSUPPORTED(reactor_environment_unavailable)`
  and the journey exits 3 with the record written; R0 still runs. A missing M05 record with no way to re-run reports
  `UNSUPPORTED(m05_study_unavailable)`. Neither is ever rendered as a decision. A third reason,
  `UNSUPPORTED(surrogate_loop_unavailable)`, is R2's under a `PROMOTABLE` verdict without a surrogate-backed loop [A1.3].

## 5. W25 — "end-to-end reactor refinement with honest evidence limits"

W25 is judged on the journey record at J and its carry or re-run at C. **PASS iff every clause holds.** A clause that
needs evidence outside both lanes' authority is `BLOCKED` (none is expected). Clause labels use the v0.2 grammar (§7.3).

| Clause | Holds iff | Assertions |
| --- | --- | --- |
| W25 (a) Rungs [A1.3] | R0 and R1 each have nine grid records (verified, or the failure recorded); R2 records M04's verdict for the bound parent with its reasons verbatim and, if not `PROMOTABLE`, zero surrogate evaluations; R3 records M05's study record (sha256, carry or re-run) with its study and candidate statuses in M05's vocabulary | A20, A21, A15 |
| W25 (b) Before/after decisions | P01 and P13 each carry t_before, t_after, j_before, j_after, e_before, e_after, their FE class, and the class equals the reference function's on those numbers | A22 |
| W25 (c) Constraints [A1.7] | every decision (R0, R1, R3, the journey's) has the parent's certified state with M05 P3's inequalities evaluated (values and margins) and its bound activity; a bound-active decision carries the bound phrase | A23, A11 |
| W25 (d) Discrepancy | per grid point, J_R0 − J_R1 and its relative value; per grid point the reported quantities of §6.1; if R2 ran, surrogate − parent per grid point and band containment counts (not a coverage estimate) | A20, A15 |
| W25 (e) Uncertainty | e_k at every verified R1 point; the indifference set; R3's noise floor e* and, when M05 reports it, the indifference half-width; the discretization statement of §6.3 item 5 | A20, A21 |
| W25 (f) Truth checks | every decision is a parent evaluation (`targeted_check` or a grid point of R1); TC-1 present and equal to the reference function's | A23, A26 |
| W25 (g) Compute cost [A1.4, A1.6] | per rung: cold experiments, store hits, wall s, against M07-budget-v1; any `BUDGET_EXHAUSTED` stated; the totals equal the store attributions | A25, A13 |
| W25 (h) Honest limits, reproducibility | the report has the twelve sections, §11 lists §6.3 verbatim, no forbidden word in generated prose, `check` and `replay` pass at C, `render` is byte-deterministic | A10, A11, A24, A61 |

**Not required for PASS:** that any FE class is `FE_CHANGED`; that R3 converges; that the decision is interior; that
the surrogate is promotable. **A FAIL** is a missing or wrong clause: a number the replay does not reproduce, an FE or
TC-1 label that disagrees with the reference function, a decision taken from R0 or R2, an unreported budget overrun, a
missing not-established list. `TC1_CONTRADICTED` is reported (the journey's decision falls back to the grid, §4.4.7),
travels as a limitation, and is a finding to the design lane about M05 — not a W25 FAIL.

### 6.4 Reproducibility [A2.4: what `replay` takes from the record]

Reactor results are class R3 (reproduce from records; M02). `replay` re-derives every journey number from the stored
experiment records and the M05 record without calling the reactor, and must be **bitwise** equal to the record (the
inner solves are deterministic: G12's live re-run is bitwise). `render` twice gives identical bytes. `examples/` gets a
README pointer to the report; "an example is a demonstration, never gate evidence by itself" holds.

### A1.1 (J3) A missing noise floor — R-420

**Ruling: the interim is confirmed, with three additions.**

1. *FE.* A parent value whose noise floor is null is **not determined** in the sense of §4.4.3, just like an
   unverified one. The pair's `t_after` is null, `missing` names the field, and the class is `FE_NOT_DETERMINED`.
   `missing` is checked in the order `t_before`, `j_before`, `e_before`, `t_after`, `j_after`, `e_after` and names at most
   one field per side, as built. The reference `fe_class` needs no change, because it keys on the null `t_after`.
2. *TC-1* is evaluated on R3's candidate values (T*, J* if P1 verified it else null, e*), **not** on P13's `t_after`,
   which is nulled when the *before* side is missing too. In this precedence:
   - `TC1_NOT_APPLICABLE` with `best_grid_T` null if T*, J* or e* is null;
   - otherwise `TC1_NO_GRID` if R1 has no verified point;
   - otherwise `TC1_NOT_APPLICABLE` with `best_grid_T` = B's T if B's e_B is null. B is never replaced by a lesser
     point that has a floor;
   - otherwise the §4.4.5 inequality.

   The `tc1` member carries `missing`: empty, or one of `t_after`, `j_after`, `e_after`, `e_B`. Generator delta
   G1–G2 (A1.9) makes the reference define both null cases.
3. *No floor is ever read as 0.* M05's `noise_floor` returning `None` at a grid point makes e_k null, with limitation
   `R1:noise_floor_unavailable`, not 0.0. The build's `m05_parent_extras` line `e = 0.0 if floor is None` is a defect,
   unreachable on the coupled loop today. A null e_k still fails W25 (e) (§14 Q2), and the indifference set is null
   (not partial) when any verified R1 point lacks e_k (as built).

*Why.* FE's first test (`FE_WORSE`, Δj < −ε) needs ε, so no class other than `FE_NOT_DETERMINED` can be justified
without it. For TC-1 there are two plausible wrong answers. Reading e_B as 0 tightens the test and biases it towards
`TC1_CONTRADICTED`. Skipping B for a lesser point that has a floor loosens it and biases towards `TC1_HOLDS`. Fixture
tc1-08 tells all three apart: the correct reading gives NOT_APPLICABLE at 663.0, e_B = 0 gives CONTRADICTED at 663.0, and
skipping B gives HOLDS at 653.0. Fixture tc1-09 is built so that reading e* as 0 gives `TC1_HOLDS`, the dangerous
direction. GC-TC1-NULL asserts all of this. *Rejected:* a separate label `TC1_NOT_DETERMINED`. The `missing` list already
says what is absent, and a record with a null floor fails W25 (e) whatever the label.

`test_a06` counts 9 fixtures; two pair-construction tests under A05, using fe-01's numbers (t_before 673.0, t_after
653.0, j_before 0.5, j_after 0.5 + 2⁻¹⁹, the present floor 2⁻²¹):
- e_before null gives `t_after` null, `missing` = [`e_before`] and `FE_NOT_DETERMINED`;
- e_after null gives the same with `missing` = [`e_after`].

With the null read as 0, both would be `FE_CHANGED` (checked against the reference `fe_class`).

### A1.2 (J4) The estimate behind "would exceed" — R-421

**Ruling: the interim is confirmed.** Before each evaluation, a rung stops when *spent + estimate* would pass its cold
or wall cap. The estimate is the largest per-evaluation cost seen so far in the rung, and never less than the prior.
The prior is R1's cold = registration `g12_facts.experiments_per_loop` (4); every other prior, cold and wall, is 0. An
evaluation that overruns its estimate stops the rung `BUDGET_EXHAUSTED`, with the overrun in `budget.spent`. Unevaluated
points are `NOT_EVALUATED(budget)`, so a rung always has nine entries. **Additions:**

1. The evaluation order is the grid order, k = 0…8 (ascending T). This makes the stop a deterministic function of the
   recorded costs.
2. A point's `wall_s` is everything the journey spends on that point: the loop solve **and** its parent extras (the
   noise floor's inner solves, the P3 re-solve). The rung's spent wall is the left-to-right binary64 sum of the points'
   `wall_s`; its spent cold is the sum of `experiments.cold` (A1.4).
3. `check` re-derives the stop from the record:

   ```
   est_c, est_w = prior_cold(rung), 0.0;  spent_c, spent_w = 0, 0.0;  stopped = False
   for k in 0..8:
       if stopped or spent_c + est_c > cap_c or spent_w + est_w > cap_w:
           require entry k is NOT_EVALUATED(budget); stopped = True; continue
       require entry k is not NOT_EVALUATED(budget)
       spent_c += cold_k; spent_w += wall_k; est_c = max(est_c, cold_k); est_w = max(est_w, wall_k)
       if spent_c > cap_c or spent_w > cap_w: stopped = True
   require budget.spent == (spent_c, spent_w) exactly; require (outcome == BUDGET_EXHAUSTED) == stopped
   ```

   Any disagreement rejects the record.

*Why.* §4.5 asked for a "would exceed" test and gave no estimator. The largest cost seen is simple and depends only on
what the record holds, and the G12 prior keeps R1's first evaluation from counting as free. *Rejected:* a fixed
worst-case estimate (G12's 361.5 s), which ties the stop to another machine's wall clock. *Rejected:* stopping only once
the cap is already passed, which allows an overrun of one evaluation by design.

*Build action.* Move the extras inside the point's timing. Implement the re-derivation in `check`. A13's tests gain two
mutations, each of which must be rejected:

### A2.4 (J27) What `replay` takes from the record — R-455

**Ruling: J27 meets §6.4. This amendment fixes the list and closes one gap.**

"Every number" means every number that is a function of the stored experiment records, the M05 record, the case files
and the registration. Measurements of time and digests of run-time artefacts are not such functions. `replay` takes
exactly these members from the record, and no others:
- for each evaluated grid point: `wall_s` and `coupling_sha256`, plus `experiments`, but only after the replay's
  served total equals the record's cold + store_hit + in_process (A25's archive count pins the split by kind at rung
  level);
- for R3: `m05_record.carried_from` and `offered` (the carry is judged at run time and, at C, by RC step 15, not by
  `replay`), a re-run's `budget.spent.wall_s`, and a refused R3's limitation codes;
- for the T* re-solve: `t_star_resolve.wall_s`, and its counts under the same total rule;
- `commit` and `environment`.

Everything else is re-derived and compared by JSON text. That includes `run_sha256`; every J, e and constraint value;
the T* re-solve's objective identity; budgets and stops; and every label. The build matches this list. Changing the
list takes an amendment.

*Gap closed (added).* When `carried_from` is `"rerun"`, the M05 record is the journey's own product, and no replay
re-derives it. M05's G10 covers only M05's committed records. The journey's replay reads T*, e* and the statuses from
the record; only J* is re-derived, through the T* re-solve. `replay` therefore also replays a re-run under `<J>/m05/`
with M05's REAL replay and requires no difference:
- it calls `m05_wo9_real.run_real(root, archive=…)` on `trust-region-study-real.experiments.json`;
- it compares the result with `m05_wo9_real.compare`, which gains a keyword `stem`, defaulting to `STEM`, so that M05's
  own behaviour is unchanged.

For a carried record nothing is added; its replay is M05's G10.

*Why.* Walls are measurements and cannot be reproduced. The coupling record holds the attempts and `cache_hit`, and a
store-served replay changes both by construction. The R3 re-run's coupling digests differ from M05's in exactly that
way.

*Rejected:* re-deriving the per-point split from the archive. The archive does not link attempts to points, and A25
already pins the totals by kind.

*Build action.* Add the `stem` keyword and the re-run replay. Add a test that a re-run whose `.experiments.json` lacks
one result makes `replay` report a difference. `scripts/m05_wo9_real.py` is in `carry.r3_files`, so the edit is one
more reason R3 re-runs at J′.
