## Context

**What R-153 asks for.** Frank's order (R-153, 2026-10-06) puts a pre-release `0.2.0a1` after M02 is `tested`. Its
watch-for asks for "a v0.2 gate of its own (the W gates that apply at that point), designed before the pre-release,
not by relaxing the v0.1 one".

**Why the v0.1 gate cannot be used.** `scripts/v0_1_gate.py` refuses every version off the 0.1 line (R-151). M02's
architect proposed a default, N3: "the v0.1 gate unchanged + W21 and W22 met, and no other claims". Frank has not
answered it.

**What v0.2 moved.** Since v0.1.1, v0.2 has moved, on purpose, several records the v0.1 gate reads or the v0.1 RC job
asserts:
- the served MCP surface (R-192, and R-234 at M02's merge);
- the support envelope (R-193);
- the CHANGELOG limitation, review-table and manifest-count tests (R-216, R-217);
- and, at M02's merge, T08.B50's content.

Each move kept the v0.1 record as released and deferred its v0.2 counterpart to "the v0.2 gate".

**What ADR 0021 says about later releases.** It is explicit: "A later release reuses D1, D2 and D4 unchanged; D3 is
per release." Its D3 acceptance of V14 (b) FAIL (2026-09-29) was for v0.1.

**What T08 §4.7 says about V17.** If the agent surface differs from R-133's carried surface, V17 is `BLOCKED` pending
Frank. The v0.2 surface differs.

## Decision

### D1. What `0.2.0a1` claims: gate set `v0.2-alpha-gate-v1` (N3's default)

**Claimed.** V11–V20, re-judged at `C_α` by T08 release spec §4, with the criteria unchanged and with the counterparts
of D3. W21 and W22, judged at `C_α` by spec §6.

**Not claimed.** W23–W27. The gate prints each of them `not claimed (v0.2-alpha-gate-v1)`, and none of them blocks. Code
`C_α` contains ships whether or not it is claimed, for example M06's web shell. Its limitations enter the envelope and
the notes; it does not enter the claims.

### D2. ADR 0021 is reused, and its D3 is per release

**Reused unchanged.**
- D1 (the RC);
- D2 (when a tag may be proposed), including D2.4's path list and version rule (revision 2);
- D4 (what the notes say);
- D5 (what is Frank's).

**D3 for this release** is the table "D3 for 0.2.0a1" below. A `FAIL` clause is releasable only with Frank's
acceptance in that table, dated on or after the alpha verdict's `Judged` date. ADR 0021's acceptance is not read.

**Frank's per-release answers.** Three answers are also preconditions of a YES, recorded in "Frank's answers for
0.2.0a1" below:
- **N3**, the claim set;
- **V17 carry**, the carry of `v17-c2`'s agent evidence (for V17 and for T08.B50's surface) across every surface change
  registered since R-133;
- **M02 N1**, publishing the `external-subprocess-v1` execution profile, which is not a sandbox.

**The cell rule.** `scripts/v0_2_gate.py` reads both tables. A cell counts only if, with `*` and backticks removed and
lower-cased, it starts with `accepted` and contains a date (spec Table T4). Any other answer, including a chosen
alternative, refuses with a request to amend the specification.

### D3. Every moved v0.1 record has a v0.2 counterpart at least as strict; the v0.1 records stay as released

Spec §5.2 lists twelve: MR-1 to MR-12. The principles:

**The surface.** The served MCP digest at `C_α` must decompose, one registered link at a time, each strip applied to
the previous one's output, to R-133's `171dd768…`, and then to `v17-c2`'s `6d13e13d…`. The 17 description texts must
be byte-identical to R-133's (spec §5.3). `scripts/t08_rc.py`'s A49 constant is a 0.1 record and is not edited. It is
not a row of the alpha's RC record, but its endpoint is asserted inside the chain.

**The envelope.**
- At `C_α` it is pinned as `v0.2-alpha-envelope-1` with `release` equal to the version being cut (R-193's watch-for).
- Its harvest covers every manifest at `C_α`, T08's included (T08 Amendment R8 4).
- After the tag it returns to R-193's working form.

**The `## v0.2.0a1` notes.**
- They name exactly the alpha envelope's limitation ids (R-216's and R-217's watch-fors).
- Their review table covers every package manifest at the candidate.
- Their gate table is `v0_2_gate.py --markdown`'s.

**The v0.1.0 notes.** Their gate-table test reads the ledger as v0.1.0 released it.

**Rules extended by their own reasoning.**
- V11 (e) also covers a real v0.1.1-emitted bundle (T08 §4.1's reasoning, applied to the predecessor release).
- T08.A34 covers the coupled-route certificates the RC job now emits.
- T08.A30 covers every extra that is new since v0.1.1, through its own audit.

**The v0.1 gate.** `scripts/v0_1_gate.py` and its test are not edited.

### D4. Version and candidate

`C_α` declares the release version itself, `0.2.0a1`, in `pyproject.toml`, `src/openflowsheet/__init__.py`, the
version-carrying fixtures and the envelope's `release`.

The tag candidate's D2.4 paths equal `C_α`'s with no version substitution. The gate requires `C`'s version to equal the
candidate's, which makes D2.4's one-occurrence allowance moot for the alpha. The allowance stays in the shared code.

A forgotten `rc` input (the 0.1 default `67c66d9`, version `0.1.0rc1`) is therefore refused, not misread.

### D6. Mechanics

**One gate script per minor line.** `scripts/v0_2_gate.py` holds a registry of gate sets. Today it has one,
`v0.2-alpha-gate-v1`, covering exactly `0\.2\.0a[1-9][0-9]*`. Any other 0.2 version is refused as not covered. M07
adds `v0.2-gate-v1`.

**`release.yml`.** It accepts canonical PEP 440 versions, `X.Y.Z` with an optional `aN`, `bN` or `rcN` where N ≥ 1. It
resolves the gate by major and minor version, as today, and marks the GitHub release as a pre-release when the version
has a pre-release segment.

**`changelog_section.py`.** It accepts the same tag forms.

**The freeze.** `main` takes no change to a D2.4 path from `C_α` to Frank's dispatch (spec Q7). The alternative is a
dispatch from a tag that Frank pushes himself.

### D7. W21's and W22's clauses, and the reading of "parent-model validation"

**The clause lists.** The blueprint bullets count over the plan rows (T08 §1):
- W21 has six clauses, (a) port mapping to (f) parent-model validation;
- W22 has four: (a) numerical verification, (b) conformance, (c) pure-component empirical validation within R-160's
  bands, and (d) sufficiency for the selected chemistry.

**The reading of W21 (f).** The PyMRM reactor is the parent model of v0.2's surrogates. Its validation is carried and
stated, not re-made. Clause (f) is met iff all four hold:
- **(f1)** the adapter reproduces the parent model run standalone (M01.A47);
- **(f2)** the group's regression suite at the pin is reproduced (T08.A61);
- **(f3)** the parent model's numerical-error evidence is carried with every result;
- **(f4)** the group's published comparison with data is cited, not re-judged, and the notes say that this project has
  compared no reactor result with data.

## Alternatives considered

- **Editing `scripts/v0_1_gate.py` to admit 0.2 versions.** Rejected: R-153 says "not by relaxing the v0.1 one", and
  the 0.1 line's gate must stay as released.
- **A separate `scripts/v0_2_alpha_gate.py`, dispatched by the pre-release segment.** Rejected: `release.yml` resolves
  one gate per minor line (`docs/RELEASING.md`, "The gate is per minor line"). A registry of gate sets keeps that rule,
  and lets M07 add 0.2.0's set without touching the workflow's resolution.
- **Claiming W21 and W22 only, without re-judging V11–V20 at `C_α`** (N3 alternative (ii)). Rejected as the default:
  the alpha's code differs from v0.1's, and a V gate not judged at `C_α` is an unstated gap. It is offered to Frank.
- **Also claiming W26** (N3 alternative (i)). Not rejected: Frank's choice. It needs a W26 verdict and gate set `v2`.
- **An RC version `0.2.0a1.dev1` with a bump at the tag** (v0.1's `0.1.0rc1` pattern). Rejected: it adds a second
  version string, and a commit, for no added evidence. The envelope's `release` is under D2.4 and must equal the
  released version, which a bump at the tag could not change.
- **Carrying ADR 0021's V14 (b) acceptance to the alpha.** Rejected: D3 is per release, and an acceptance dated before
  the evidence it accepts is the waiver ADR 0021 rejects.
- **Reading V17 as carried by R-192.** Rejected: R-192 registered a digest. T08 §4.7 makes the carry Frank's decision
  (F5), and R-133 was his.
- **Editing `scripts/t08_rc.py`'s A49 constant to the v0.2 digest.** Rejected: that rewrites a 0.1 release record
  (R-192).
- **The stronger reading of W21 (f)** (this project compares reactor results with experimental data). Rejected as the
  default: that is validation of the reactor's physics, which blueprint §9.1 keeps as separate evidence and M07's truth
  checks own. The data's use also awaits Frank's statement (T08 R3 8 (b)). It is offered to Frank (spec F-α4); under it,
  W21 (f) would be `BLOCKED`.
- **Leaving T08's manifest out of the alpha's harvest.** Rejected: its limitations (PTC experimental, V14 (b)) are true
  of the alpha. The alpha's notes must name every envelope row, and T08 Amendment R8 4 handed the manifest to "v0.2's
  harvest".
