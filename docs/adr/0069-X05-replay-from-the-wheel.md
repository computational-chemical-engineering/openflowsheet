## 1. Decision in one sentence

The wheel carries `requirements.lock` as package data, every `environment()` call — checkout and installed alike —
reads that packaged lock and records its SHA-256 only after checking each of the nine distributions of the registered
runtime closure against it by exact version string, else records `""` and carries the failing distributions as findings
that replay names in its reason; so an installed package at the lock records `ead4edf1…` exactly as the checkout does,
and its bundles replay `exact_replay` where ADR 0007 D4 allows, and never otherwise.

## 2. Context (recon 2026-11-07; paths under `src/openflowsheet/`)

  `_checkout_lock(__file__)` (`:185-217`): only inside a source checkout, `root/requirements.lock`; else `""`. Nothing
  checks that the installed distributions are the locked ones: a checkout with a stale virtual environment records the
  lock's hash and replays `exact_replay` today.
- `run/replay.py:73 decide_mode`: an empty `lock_sha256` on either side → `inspected_archived_results`, reason
  `"the dependency set is unknown on {side}: no lock file was found, and two unknowns are not a match"` (`:93-102`);
  differing hashes → inspected; then platform, BLAS, threads (unchanged here).
- `requirements.lock`: 47 lines, 43 pins (`name==version`, no hashes), SHA-256
  `ead4edf1ea3577287a7576d56a9e5db550e5a5be459dd634b10806fdc655b9c4`. It is the development environment's freeze

  transitive runtime ones float. The wheel carries no lock.
- `resources.py` (T08 W4.2): `_data/` holds **symbolic links** to the single repository copies; the wheel and sdist
  carry the bytes; `resources.packaged(relative)` reads the same bytes in a checkout and an installed wheel; T08.A43's
  build check compares them file by file. The packaged lock follows this pattern exactly.
- The schema's `environment` object is closed (`schemas/run-manifest.schema.json:66-98`), part of the frozen core
  (R-941; ADR 0067 `:33`).
- F0: M7 replays the 52 bundles of `tests/fixtures/f0/v0.3.0-bundles` (each records `ead4edf1…`, written on the

## 3. Decision

### D1. The packaged lock: one file, one path, read in the checkout and the wheel alike

1. `requirements.lock` at the repository root stays the single copy (its bytes, its hash `ead4edf1…`, `make lock`, CI's
   `-r`/`-c` uses: all unchanged). `src/openflowsheet/_data/requirements.lock` is a **symbolic link** to
   `../../../requirements.lock`; `resources.PACKAGED` gains the file entry `"requirements.lock"`; `pyproject.toml`'s
   `[tool.setuptools.package-data] openflowsheet` gains `"_data/requirements.lock"`. The wheel carries the bytes at
   `openflowsheet/_data/requirements.lock`, the sdist at `src/openflowsheet/_data/requirements.lock` (X05.A20).
2. `environment()` with no argument reads `resources.packaged("requirements.lock").read_bytes()` and labels it
   `openflowsheet/_data/requirements.lock` (the `{where}` of D5's templates; a fixed string, never an absolute path).
   With `lock_path`, it reads that file and labels it `os.fspath(lock_path)`. An `OSError` on reading is "no bytes".
   The file is read on every call.
3. `_repository_lock` and `_checkout_lock` are deleted. No other file is ever read for the lock: a `requirements.lock`
   anywhere above an installed package — the R-140 defect — cannot be reached (X05.A13, A14).

### D2. The verification rule — `openflowsheet.run.lock.verify_lock(data, installed, where)`

A pure function: `data: bytes | None`, `installed: Callable[[str], str | None]`, `where: str` →
`(lock_sha256: str, findings: tuple[str, ...])`. It never raises (X05.A09).

1. `data is None`, or `data` is not strict UTF-8 → `("", (F1,))`.
2. The text is split on `"\n"`; line *k* (1-based) is reduced to the part before its first `#`, stripped with
   `str.strip()`. An empty remainder is skipped. A non-empty one must full-match
   `NAME==VERSION`, `NAME = [A-Za-z0-9]([A-Za-z0-9._-]*[A-Za-z0-9])?`, `VERSION = [A-Za-z0-9][A-Za-z0-9.+!_-]*`, and its
   PEP 503 name (runs of `-_.` → `-`, lower case) must not repeat an earlier line's. The first line that fails →
   `("", (F2,))` with `{line}` = *k* and `{text}` = Python's `repr()` of the line as decoded, without its `"\n"`.
3. For each member of the registered closure (D3), **in the registered order**: not pinned in the lock → F5;
   `installed(name)` raises → F6 with `{error}` the exception's class `__name__`; returns `None` → F3; returns a string
   other than the pin, compared **as strings** → F4. Every member is checked; nothing short-circuits.
4. No findings → `(sha256(data).hexdigest(), ())`: the hash of the bytes as read, comments, blank lines and the lines
   outside the closure included. Any finding → `("", findings)`.

Lock lines outside the closure are hashed and not checked (X05.A06); installed distributions outside the closure are
not looked at. Names are normalised for the comparison only (X05.A07).

**The read** (`openflowsheet.run.lock.installed_version(name)`, the `installed` that `environment()` passes):
`importlib.metadata.distribution(name)`; `PackageNotFoundError` → `None`; a found distribution whose
`.metadata.get("Version")` is not a non-empty `str` → `TypeError` (so F6 names `TypeError`, whatever the Python's own
behaviour for a missing `Version`); any other exception propagates to `verify_lock` as F6. The outcome — a version,
`None`, or the raised class — is memoised per process (D6).

### D3. The runtime closure: registered, measured, no extras; its direct members pinned in `Requires-Dist`

**Registered runtime closure (D3; 9 distributions, PEP 503 names, in this order):** `attrs`, `casadi`, `jsonschema`, `jsonschema-specifications`, `numpy`, `pyyaml`, `referencing`, `rpds-py`, `scipy`.

1. It is the transitive closure of `[project].dependencies` **without extras**, markers evaluated with `extra = ""` in
   the measuring environment (Python 3.13, Linux, both registered architectures). It is a constant in
   `openflowsheet.run.lock.RUNTIME_CLOSURE`, not computed at run time: computing it needs `packaging` (not a runtime
   dependency) and an installed `openflowsheet` distribution's metadata, which a checkout may not have or may have
   stale (measured: `.venv` carries `openflowsheet==0.1.1` beside `src/`). X05.A10 measures it against the constant.
2. **The four transitive members float** (Amendment 1, §14; Frank's Q-F1 = no): `[project].dependencies` pins the
   five direct members exactly and does not name `attrs`, `jsonschema-specifications`, `referencing` or `rpds-py`. An
   install constrained by the shipped lock (`pip install -c requirements.lock openflowsheet`) installs the closure at
   the lock and verifies; a plain, unconstrained `pip install openflowsheet` verifies only if the resolver happens to
   pick the lock's versions, and otherwise records `""` naming each member off the lock, which the replay reason names
   (D5; X05.A25).
3. **Extras are outside the identity**, before and after X05: `server` (no numerics), `coolprop` (hash-pinned in
   `requirements-coolprop.lock`, guarded by the provider's own `coolprop_version_mismatch`, ADR 0046), `nlp` and `lca`
   (their audited environments), `dev`. Their distributions are not checked and `lock_sha256` attests nothing about
   them.
4. A change of the lock's pins for a closure member, or of the closure (a new transitive dependency), changes the lock
   bytes and so `lock_sha256`; X05.A10 and A25 fail until `RUNTIME_CLOSURE` and the pins follow, and the reference
   values are re-emitted by the package that changes the lock.

### D4. What `lock_sha256` attests, and checkout against wheel

1. After X05, `lock_sha256 = h ≠ ""` attests: when the environment was captured, the lock the build reads (D1) had
   SHA-256 *h*, parsed under D2, and each of the 9 distributions was visible to `importlib.metadata` at exactly the
   version *h* pins. `""` attests that this was not established, and why is in the findings (D5).
2. **A checkout and an installed wheel that verify the same bytes record the same hash.** A bundle written in CI's
   checkout replays from a verified install with ADR 0007 D4's mode decided by platform, BLAS and threads as before:
   `exact_replay` on the same platform identity with pinned threads, `compatible_reproduction` across the registered
   pair. The identity of `openflowsheet`'s own code was never `lock_sha256`'s to attest (the lock has always excluded
   the project itself).
3. **The checkout is not exempt.** A checkout whose environment is off the lock now records `""` where it recorded the
   hash before — the same false-exact path R-140 refused for the wheel. A matched checkout's record is unchanged
   (X05.A11, A12, A23).
4. ADR 0007 D4's mode table is unchanged: "same lock-file hash" now means "the same verified lock".

### D5. Findings and reasons: no schema change; the reason states the match

The environment **document** keeps its eight keys and the schema is untouched. `Environment` gains an in-memory
attribute `lock_findings: tuple[str, ...]`, `field(default=(), compare=False)`, **not** in `as_document()` and not in
equality; `environment()` sets it from D2; an `Environment` read from a manifest has `()`. For every `Environment`
that `environment()` returns, `lock_findings` is non-empty iff `lock_sha256 == ""`.

`decide_mode`'s first branch (either hash empty) keeps the prefix `the dependency set is unknown on ` and returns one
reason, rendered from these templates (`{findings}` = the current side's `lock_findings` joined with JOIN, or NONE when
it has none); every other branch is unchanged:

| Key | Template | Used when |
| --- | --- | --- |
| F1 | `the lock {where} is missing or unreadable` | no bytes, or not UTF-8 |
| F2 | `the lock {where} is malformed at line {line}: {text}` | first line outside D2.2's grammar, or a repeated name |
| F3 | `{name} is not installed, the lock pins {locked}` | `installed` returns `None` |
| F4 | `{name} is {installed}, the lock pins {locked}` | a different version string |
| F5 | `{name} is in the runtime closure but not in the lock` | a closure member without a pin |
| F6 | `{name}'s installed metadata could not be read: {error}` | `installed` raises |
| R_ARCHIVE | `the dependency set is unknown on the archive's side: the archive recorded no verified lock, so nothing is known to match` | recorded `""`, current verified |
| R_THIS | `the dependency set is unknown on this side: this side's lock did not verify ({findings})` | recorded verified, current `""` |
| R_BOTH | `the dependency set is unknown on both sides: the archive recorded no verified lock, and this side's lock did not verify ({findings}); two unknowns are not a match` | both `""` |
| NONE | `no verification recorded` | a current `""` with no findings (a constructed `Environment`) |
| JOIN | `; ` | the separator of findings |

The archive's findings are not recorded (that would be a schema change); the archive's side says only that it recorded
no verified lock. The current side's findings name each failing distribution: that is "the environment match stated".

### D6. Cost: one read per closure member per process

`installed_version` memoises its outcome per process (a module-level dict; idempotent, so a race is harmless). The lock
bytes are re-read and re-verified on every `environment()` call (68 µs measured), so a `lock_path` call, or a lock
deleted mid-process, is seen. Without the memo every `environment()` call would pay about 5.5 ms warm against its own
0.96 ms. X05.A19 counts the reads. No timing is asserted.

### D7. The frozen core, T08.A19 and L41

1. **ADR 0067 step 4** ("ADR 0007 D4's mode from lock, platform and threads, unchanged") stays true and is not amended:
   the mode is the same function of the two recorded documents; what changes is when a non-empty hash is recorded and
   the wording of one reason. The environment record's field set (ADR 0067 `:33`) is unchanged.
2. **T08.A19** is retired as a live check from X05 on and restated: (a) "the checkout records `ead4edf1…`" → X05.A11;
   (b) "an installed package beneath a stray lock records `""`" → X05.A13 and A14 (it now records the packaged lock's
   hash, and still never the stray's); (c) "the installed CLI's bundle replays inspected/`NOT_RUN`" → X05.A16 and A17
   (it now replays `exact_replay`/`MATCH`; the never-`MATCH` property moves to the unverified cells). The tests of
   `_checkout_lock` go with the function. The T08 records stay as judged.
3. **L41** is narrowed, not dropped (X05.A24): "A bundle written by an installed package or a checkout whose runtime
   closure (the 9 distributions of ADR 0069 D3) is not at the packaged lock `ead4edf1…` records no dependency-set
   identity: its `lock_sha256` is empty, every replay of it is `inspected_archived_results` / `NOT_RUN`, and the
   replaying side's failing distributions are named. Optional extras are not part of the identity."

## 4. Alternatives rejected

- **Check every lock line** (B12's literal "every locked distribution"). The lock is the development freeze; a clean
  install of the wheel has none of `pytest`, `ruff`, `mypy`, `mcp`, …, so no installed package could ever verify
  (states V01 and V03 verify under D2 and fail under this rule). The goal of B12 is unreachable on
  its own wording; the closure is what the wheel's code imports.
- **Ship the lock (or its hash) and record it unchecked.** R-140's rejected alternative, still rejected: a false
  `exact_replay` between environments nobody compared.
- **Compute the closure at run time** from `Requires-Dist`. Needs `packaging` at run time and the project's own
  installed metadata, which is absent or stale in checkouts (measured: `openflowsheet==0.1.1` in `.venv`).
- **PEP 440 version equality.** `2.2.4.0 == 2.2.4` and `==2.2.4` admits `2.2.4+local`, another build. Exact strings are
  stricter and simpler (V32, V33).
- **Compare imported modules' `__version__`.** Needs a name map (`pyyaml` → `yaml`, `rpds-py` → `rpds`) and importing
  CasADi at manifest time; metadata is what the lock pins.
- **Hash-pinned lock and per-file `RECORD` verification.** Stronger (it would see a rebuilt wheel under one version),
  but the lock has no hashes and the one rebuild measured to matter, BLAS, is already D4's `blas.version` check. Not
  now; §10.
- **A new environment field** (`lock_source`, `lock_findings`) — ADR 0019 Amendment 14 on a closed, frozen schema, for
  information the replaying side recomputes; the only gain is the archive's own findings (Q-F3).
- **Keep `_checkout_lock` for checkouts, the packaged lock for installs.** Two code paths and two answers to one
  question; the symbolic link gives the checkout the same bytes through the same path.
- **Cache the whole verification per process.** A `lock_path` call or a changed file would get a stale hash; the
  versions are the expensive part (D6).
- **No memo.** About 6× the cost of every `environment()` call (D6).

## 5. Migration and compatibility

- Bundles written by an installed package before X05 recorded `""`: they replay inspected/`NOT_RUN`, reason R_ARCHIVE
  (mode unchanged, text changed).
- Bundles written by a checkout before X05 recorded the file's hash unverified: replayed as before in a checkout, and
  now also from a verified install (§10 states what this does not establish about them).
- The 52 F0 bundles: unchanged in the checkout (F0 PASS, X05.A23); from the wheel, X05.A22.
- No schema, fixture, catalogue code or served tool changes. `manifest_sha256` of a new manifest written by an
  installed package changes, because its `lock_sha256` is no longer `""` — the point of the package.
- Environments the build must measure before merging: Q-N1.

### 6.2 End-to-end constructs and the replay matrix

- **Installed (test):** `src/openflowsheet` copied (`shutil.copytree`, links followed) into a scratch
  `…/site-packages`, run with that directory as `PYTHONPATH` from outside the checkout. **Installed (CI):** the RC
  wheel in a fresh virtual environment outside the tree (the existing `clean-install` job).
- **Stray:** a file `requirements.lock` in the directory above the environment, containing the packaged lock's bytes
  followed by `# stray copy, not the packaged lock\n` (SHA-256 in the JSON, `c2a8f1c1…`). It would verify if it were
  read, so only reading it is what X05.A13 can catch.
- **Shadow:** a directory placed first on `PYTHONPATH` holding only `numpy-2.2.5.dist-info/METADATA`
  (`Metadata-Version: 2.1`, `Name: numpy`, `Version: 2.2.5`): `importlib.metadata` sees numpy 2.2.5 while the real
  numpy is imported, so the solve still runs and exactly one finding results.
- **No packaged lock:** the installed copy with `_data/requirements.lock` deleted, the stray present.
- **States:** `installed`, `checkout`, `installed-off` (installed + shadow), `checkout-off` (checkout + shadow).
  **Bundles:** `on` = `SYN-001-nominal` written by `installed`'s CLI; `off` = written by `installed-off`'s CLI. Every
  process pins the three thread variables to `1`.

The 8 cells (the JSON's `end_to_end.replays` carries the exact reason strings):

| State \ bundle | `on` (records `ead4edf1…`) | `off` (records `""`) |
| --- | --- | --- |
| `installed` | `exact_replay` / `MATCH` | inspected / `NOT_RUN`, R_ARCHIVE |
| `checkout` | `exact_replay` / `MATCH` | inspected / `NOT_RUN`, R_ARCHIVE |
| `installed-off` | inspected / `NOT_RUN`, R_THIS | inspected / `NOT_RUN`, R_BOTH |
| `checkout-off` | inspected / `NOT_RUN`, R_THIS | inspected / `NOT_RUN`, R_BOTH |

with `{findings}` = `numpy is 2.2.5, the lock pins 2.2.4`.

### 6.3 Assertions

25 assertions. Tolerance is **exact** for every one: each compares strings, byte digests, enumerations or counts, which

## 10. What this ADR does not establish

- **That a pre-X05 bundle with a non-empty hash was written at the lock.** Its hash attests only that the checkout's
  lock existed (T08.A19 (a)); X05 does not re-judge archives. The F0 bundles were written by CI-equivalent runs at the
  lock, which F0's M7 `MATCH` corroborates but does not prove.
- **Build identity under one version string.** Two builds of `numpy 2.2.4` (PyPI, conda-forge, a source build) verify
  alike; the lock has no hashes. BLAS is the one build-level check (ADR 0007 D4's `blas.version`).
- **That the metadata read is the module imported.** `importlib.metadata` reports the first distribution on `sys.path`;
  a `sys.path` arranged so that it differs from the imported package (the shadow construct does this on purpose) is
  read as the metadata says. In the shadow's direction the error is safe (`""`); the other direction needs a
  deliberately inconsistent environment.
- **Anything about the extras** (D3.3), the reactor or NLP environments' own locks, or F8's data locks (ADR 0061 D10).
- **The release procedure's provenance hash** (`scripts/t08_rc.py:154`, the checkout file's hash, unverified) — the
  release procedure's to change, not X05's.
- **Platforms or Pythons outside the registered pair.** The closure is measured on Python 3.13 and the two Linux
  architectures; a marker that differs elsewhere is not covered, and replay there is inspected anyway (ADR 0007 D4).
- **Performance** beyond the measured costs of §2; no timing is asserted.
- **Empirical validation** of anything: this is identity bookkeeping, verified by construction and by tests.
