## The architect's own summary (for orientation, not as evidence)

F1: one closed descriptor envelope; registry-computed self-hash = a v2 method's `implementation_sha256`; capability
tokens `space:name[:level]`, requirements in CNF; pure `admit()` refusing `capability_missing(...)` (kind
`not_supported`); built-in JSON tables generated by a script that does not read `MODEL_BASES`, legacy admission via
reserved `legacy:` tokens — 31 units × 7 methods, 54 admitted / 163 refused, claimed equal to the live `MODEL_BASES` (the
architect counted 30 units, 54 pairs); entry points sorted by distribution and name; install = trust boundary; evidence
class `core`/`reviewed`/`unreviewed` as notice `extension_unreviewed`, never hashed; the union of legacy self-hash sets
must equal F0's M9 set (35 files, R-940). One new kind `correlation_form`. F3: `record-v2` schema; identity = canonical
JSON minus one closed `volatile` member after a fixed normaliser; anchor derived per Q2.R2 and stored; per-project
content-addressed store with a Windows write protocol and path-length refusal; data lock derived, its SHA =
`data_sha256`; two-layer rights register outside every hash; legacy importer for 7 files / 149 records against a
committed index. Interfaces: ADR 0019 Amendment 7 (`list_capabilities`, `check_admission`) and Amendment 8 (a `Records`
protocol with five operations including `assess_rights`, a departure from the note's four). New schemas
`extension-descriptor`, `registry-snapshot`, `record-v2`, `data-lock`.

## Look hardest at

- Identity: does any part of F1/F3 move a legacy hash, fingerprint, cache key or replay (F0 M1–M9)? Is "the registry
  computes the self-hash = `implementation_sha256`" consistent with S1 and the existing `implementation_sha256` values?
- The `MODEL_BASES` equality claim (30 vs 31 units): is the proof an exact set equality a test can check?
- Determinism of `registry_sha256` and the data-lock SHA across platforms and install orders; failure modes of entry-point
  discovery (broken plugin, duplicate namespace) — loud, typed, and not able to change a core admission.
- Whether the `unreviewed` flag truly reaches every result that used an unreviewed extension (R-931), and cannot be lost.
- Whether the work orders can be built in 0.5 without a further design decision, and whether each has a falsifiable
  acceptance test.
- Core vs preview split against the W1 freeze.
